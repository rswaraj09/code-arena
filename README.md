**An AI-era coding assessment and learning platform** — contests, workshops, assignments and quizzes, with sandboxed automated evaluation and a real-time leaderboard. Built for classrooms, coding clubs, and placement training, in the shape of a real SaaS product rather than a single-file demo.

> Status: active build. Frontend scaffold and backend API are both in place; see [What's built vs. what's next](#whats-built-vs-whats-next) for the honest breakdown.

## Overview

CodeArena lets a trainer spin up a coding contest, workshop, or assignment; students solve problems directly in an in-browser Monaco editor; submissions are compiled and run inside disposable, resource-limited Docker containers; and results flow straight into a live-updating leaderboard. Admins oversee the whole platform — users, trainers, contests, and system-wide analytics.

It's split into two independently runnable pieces:

| | |
|---|---|
| **`frontend/`** | React 19 + Vite. Role-based dashboards, the coding workspace, contests, leaderboard. |
| **`backend/`** | Spring Boot 3.3 / Java 21. Auth, problems, the Docker judge, contests, WebSocket leaderboard broadcast. |

## Features by role

**Students** — register/login (JWT, email OTP verification), browse and solve problems, run code against custom input, submit for grading against hidden test cases, join contests, track rank and solved count, view submission history.

**Trainers** — create problems with visible/hidden test cases, bundle problems into timed contests, monitor submissions (approval gate before an account can publish, so a trainer signup goes through admin review first).

**Admins** — approve trainers, oversee all contests and the shared problem bank, platform-wide analytics dashboard.

## Tech stack

**Frontend**
React 19 · Vite · React Router · Redux Toolkit · MUI · Tailwind v4 · Monaco Editor · TanStack Query · Axios · Chart.js · Framer Motion

**Backend**
Spring Boot 3.3 (Java 21) · Spring Security + JWT · Spring Data MongoDB (MongoDB Atlas) · Spring WebSocket (STOMP) · jjwt · Lombok · MapStruct · springdoc-openapi (Swagger)

**Execution & infra**
Docker (sandboxed per-language judge containers: Java, Python, C++, C, JavaScript) · Docker Compose · GitHub Actions (CI/CD, planned)



## Getting started

### 1. Backend

```bash
cd backend
mvn spring-boot:run
```

Runs on the `dev` profile by default — in-memory H2, no MySQL needed to try it. Swagger UI: http://localhost:8080/swagger-ui.html. **Run/Submit need the judge images built first** — see [The sandboxed judge](#the-sandboxed-judge) below. Full details, including Docker Compose with MySQL, in `backend/README.md`.

### 2. Frontend

```bash
cd frontend
npm install
cp .env.example .env   # point VITE_API_BASE_URL at the backend above
npm run dev
```

Opens at http://localhost:5173. Full details in `frontend/README.md`.

> **Note:** the frontend currently renders mock data for problems, dashboards and the leaderboard so it's fully clickable standalone. Wiring it to the live backend endpoints is the natural next step — both READMEs point at exactly where to make that swap.

## The sandboxed judge

```bash
cd backend/docker
./build-judge-images.sh
```

Builds `codearena/java`, `codearena/python`, `codearena/cpp`, `codearena/c`, `codearena/javascript`. Each submission then runs in a fresh container with a CPU cap, a memory ceiling, no network access, a process-count limit (fork-bomb protection), and a wall-clock timeout enforced both inside and outside the container. The full reasoning and exact flags are in `docs/docker-sandbox-guide.md`.

## API documentation

Once the backend is running: **http://localhost:8080/swagger-ui.html** (OpenAPI 3, generated by springdoc — every endpoint, request/response shape, and the JWT bearer auth scheme, live from the code rather than hand-maintained).

## What's built vs. what's next

**Built:** JWT auth with email OTP + password reset, role-based access (student/trainer/admin), problem CRUD with hidden/visible test cases, the full Docker sandboxed judge (run + submit), contests with registration, a WebSocket-broadcast leaderboard, the complete React UI shell for every role including the Monaco coding workspace.

**Not yet built** (routed and stubbed on the frontend, absent on the backend — same boundary on both sides):
- Assignments (deadlines, PDF instructions, late-submission detection)
- Quizzes (MCQ/true-false/fill-in-the-blank, section timers, auto-submit)
- Certificates (QR-verified PDF generation)
- Notifications (email reminders for contests/deadlines)
- Redis caching for the leaderboard (documented upgrade path once contest sizes justify it)
- CI/CD workflow files (`.github/workflows/`)

Each backend module so far follows the same shape (`entity → repository → service → controller → dto/`), so the next ones can copy that pattern directly — see the "Convention going forward" note in `backend/README.md`.

## Environment variables

Each piece has its own `.env.example` with inline comments:
- `frontend/.env.example` — just the backend API base URL.
- `backend/.env.example` — DB connection, JWT secret/expiry, CORS origins, judge resource limits. Copy to `.env` before `docker compose up`; see `backend/README.md` for the one gotcha (Spring Boot itself doesn't read `.env` files — only Docker Compose does that substitution).
